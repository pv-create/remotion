# Правила motion-системы «BACKEND ЗА 30 СЕКУНД»

Этот файл — свод правил для агента, который пишет код Remotion-выпусков.
Скопируйте его как `AGENTS.md` (Codex) и/или `CLAUDE.md` (Claude Code) в корень репозитория.

Ниже — жёсткие правила. Их нельзя «улучшать» на своё усмотрение: система
существует, чтобы выпуски были одинаковыми. Если задача требует нарушить
правило — сначала спросите.

---

## 1. Формат

- Композиция 1080×1920, 30 fps, длительность 900 кадров (30 секунд).
- Все длительности — в кадрах, не в секундах и не в миллисекундах.
- Поля кадра: 92 px по бокам, 200 px сверху, 180 px снизу.
- Схема живёт в центральной половине кадра и не выходит из неё.
- Нижние 16 % кадра — зона субтитров. Там не рисуется ничего другого.

## 2. Цвет

| Токен    | Значение  | Роль |
|----------|-----------|------|
| `paper`  | `#F1EDE3` | фон кадра, всегда |
| `ink`    | `#16130F` | текст, обводки, офсетные тени, кадр вывода |
| `accent` | `#DFA94C` | «работает»: активные слоты, заполнение, решение |
| `alarm`  | `#C4552F` | «болит»: предел, отказ, стоимость |
| `muted`  | `#9A9287` | неактивное состояние, надзаголовки, подписи |
| `line`   | `#CFC7B4` | контур пустого слота |

Правила:

- `accent` занимает не более 15 % площади кадра и всегда означает «включено /
  происходит сейчас».
- `alarm` живёт только в бите `hook`. Он уходит ровно в тот кадр, где появляется
  решение.
- `accent` и `alarm` никогда не присутствуют в одном кадре одновременно.
- Никаких градиентов, никаких новых цветов. Нужен ещё оттенок — значит, нужно
  другое решение.
- Единственный инверсный кадр в выпуске — бит `outro` (фон `ink`).

## 3. Типографика

Шрифты: Montserrat (600/700/800/900) и IBM Plex Sans (400/500). Моно —
IBM Plex Mono, только для служебных подписей, не в кадре.

| Роль | Стиль | Размер @1080 |
|------|-------|--------------|
| Надзаголовок | Montserrat 700, caps, tracking `.2em`, `muted` | 30 px |
| Заголовок | Montserrat 900, caps, line-height `.92`, tracking `-.02em` | 112 px |
| Лид | IBM Plex Sans 400, line-height `1.35` | 42 px |
| Субтитр | Montserrat 800, по центру, максимум 2 строки | 46 px |
| Показание | Montserrat 900, табличные цифры, tracking `-.02em` | 64 px |
| Подпись данных | Montserrat 700, caps, tracking `.16em`, `muted` | 26 px |

- Заголовки — всегда капсом. Лид и субтитры — обычным регистром.
- Ниже 26 px в кадре 1080 текста не бывает.
- В каждый момент один доминирующий элемент; остальное — `opacity: .4`.

## 4. Форма

- Слот: 74×74 px, радиус 12 px, обводка 2.5 px `ink`, офсетная тень
  `5px 5px 0 ink`. Пустой слот: обводка `line`, без тени, цифра `muted`.
- Метр: высота 16 px, радиус 9 px, обводка 2.5 px `ink`, заполнение `accent`.
- Стикер: без скруглений, наклон ±3…5°, фон `accent` (или `alarm` в hook),
  текст Montserrat 800. Не больше одного стикера в кадре.
- Фон: сетка с шагом 24 px, линии `ink` при 5 % непрозрачности.
- Тени только офсетные и только чёрные. Никаких размытых теней.

## 5. Движение

Три кривые, больше нет:

```ts
out    = Easing.bezier(.16, 1, .3, 1)      // текст, рост метра, переезд
travel = Easing.bezier(.45, .05, .55, .95) // курсор, дрейф камеры, смена бита
pop    = spring({ damping: 12, stiffness: 180 }) // слоты, стикеры, бейдж
```

Четыре длительности плюс пауза:

```
micro  6f   бейдж, клик, появление субтитра (только opacity)
elem  10f   слот, стикер, строка текста
block 18f   заголовок целиком, схема, метр
beat  24f   переезд объекта, смена сцены
hold  18f   пауза перед событием: не двигается ничего
```

Правила:

- Одновременно двигается один смысловой объект.
- Каскад внутри блока: шаг `stagger = 3f`, не больше пяти элементов подряд.
- `hold` — обязательный элемент композиции: 18 кадров тишины перед событием,
  иначе событие теряется в общем шевелении.
- Любое показание анимируется от предыдущего значения (`interpolate` +
  округление). Готовое число на экране запрещено.
- Причина опережает следствие: метр растёт первым, слоты включаются с
  `lag = 8f` и далее по `stagger`.
- Между битами сквозной объект не исчезает, а переезжает и меняет масштаб
  (`Handoff`). Один такой объект на выпуск.
- Дрейф камеры: масштаб всей композиции 1.0 → 1.05 за 900 кадров, кривая
  `travel`. Задаётся обёрткой выпуска, сцены о нём не знают.
- Последний кадр композиционно совпадает с первым — выпуск зацикливается.

## 6. Структура выпуска

Четыре бита, всегда в этом порядке:

```
hook    0–90f    Сломанное состояние. 100 %, alarm, один инстанс не тянет.
                 Заголовка нет. Только проблема.
answer  90–300f  Заголовок как ответ на проблему. Каскад: надзаголовок →
                 бейдж → линия → заголовок → лид.
event   300–690f Метр ведёт, слоты догоняют. Перед началом hold 18f.
outro   690–900f Схема переезжает наверх и уменьшается, инверсный кадр,
                 вывод одной строкой, крючок следующего выпуска.
```

## 7. Компоненты

Один компонент на элемент кадра. Внутри компонента — только его собственное
движение; композиция его не переопределяет.

| Компонент | Пропсы | Движение |
|-----------|--------|----------|
| `TitleBlock` | `kicker, badge, title, lead` | каскад 4 шага, `out`, шаг 3f |
| `Meter` | `label, from, to, tone` | рост 14f, `out`; число догоняет полосу |
| `SlotRow` | `total, active, lag` | `pop`, старт от кадра метра + `lag`, шаг 3f |
| `Sticker` | `text, tone, tilt` | `pop`, 10f, overshoot |
| `Captions` | `beats[]` | только opacity, 6f, зона не двигается |
| `Handoff` | `children, to, scale` | 24f, `out` |
| `Spotlight` | `target, zoom` | курсор 18f `travel`, клик 3f, зум ≤ 1.4× |
| `Outro` | `verdict, next` | `outroRise`, 18f, `out` |

## 8. Время задаёт `Sequence`, не компонент

- Компонент анимируется от нулевого кадра своей последовательности
  (`useCurrentFrame()` внутри `<Sequence>`).
- Сдвиги — только через `from`. Никаких `frame - 137` внутри компонентов.
- Тогда перемонтаж выпуска не ломает анимации.

## 9. Текст выпуска — данные

Заголовок, лид, субтитры по битам, показания, стикеры лежат в JSON выпуска
(см. `types.ts` и `example-episode.json`). Новый выпуск — новый файл данных,
не новый код. Если для выпуска нужен новый компонент — значит, система чего-то
не умеет, и это отдельная задача.

## 10. Чего не делать

- Не добавлять цвета, шрифты, кривые и длительности вне таблиц выше.
- Не размывать тени, не скруглять стикеры, не наклонять что-либо кроме стикера.
- Не анимировать единицы измерения, надзаголовки и зону субтитров.
- Не двигать больше одного смыслового объекта одновременно.
- Не показывать готовые числа.
- Не оставлять нижние 16 % кадра пустыми и не заезжать в них схемой.
